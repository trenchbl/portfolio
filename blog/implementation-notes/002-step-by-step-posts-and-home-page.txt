STEP 002 - POSTS: DATA MODEL AND HOME PAGE
==========================================


1. GOAL
-------
At the end of this step you will have:
- A posts table created by Liquibase, plus sample posts that only load in
  development
- A Post JPA entity, a repository, and a service layer
- A shared Thymeleaf layout (head, header with navigation, footer) and a
  stylesheet
- A home page listing published posts, newest first, and an About page
- Tests for the repository (against real MySQL) and for the controller
  (web layer only)


2. CONCEPTS
-----------
Package by feature
  Code is grouped by what it is about, not by what kind of class it is:
    com.blog.post   - Post, PostRepository, PostService, PostSummary
    com.blog.web    - controllers
  The repository is package-private, so only classes in com.blog.post can
  use it. Controllers have to go through PostService. This keeps database
  access in one place as the app grows.

Drafts without a status column
  A post is published when published_at has a value and is a draft when it
  is NULL. One nullable column records both whether and when a post was
  published, so the two can never contradict each other. Step 005 builds
  the draft/publish buttons on top of this.

Entities stay inside the service layer
  With open-in-view=false, the database session is closed by the time the
  template renders. The service therefore returns PostSummary, a small
  immutable record holding exactly what the list page needs, instead of
  the Post entity. Templates cannot trigger lazy-loading queries, and the
  service decides what data leaves the transaction.

Sample data only in development: Liquibase contexts
  The sample-posts changeset has contextFilter="dev". Liquibase runs a
  context-filtered changeset only when that context is active:
  - application.properties sets spring.liquibase.contexts=dev, so running
    the app locally loads the samples.
  - Tests use the "test" profile, which sets the context to "test", so they
    start with an empty table and create exactly the data they need.
  - The production profile (step 009) will not include "dev".
  Careful: if no context is set at all, Liquibase runs every changeset,
  including the dev ones. That is why the context is always set explicitly.

Layout with Thymeleaf fragments
  fragments/layout.html defines three reusable pieces with th:fragment:
  head(title), header(active), and footer. Each page pulls them in with
  th:replace. The parameters let each page set its <title> and highlight
  its own navigation link. This needs no extra library.

Fixed locale
  Thymeleaf formats dates in the visitor's language by default, so a
  browser set to German would show "1 Oktober 2026" on an English page.
  spring.web.locale-resolver=fixed together with spring.web.locale=en keeps
  every date in English.

Two kinds of tests
  - @DataJpaTest starts only JPA, Liquibase, and the datasource, here
    against a Testcontainers MySQL. It tests that the query is correct on
    the real database.
  - @WebMvcTest starts only the web layer. PostService is replaced by a
    Mockito mock (@MockitoBean), so the test checks what the page shows for
    given data, without a database, in about a second.

3.1 Create the posts table

  Create blog/src/main/resources/db/changelog/changes/001-create-posts-table.xml:

    <?xml version="1.0" encoding="UTF-8"?>
    <databaseChangeLog
            xmlns="http://www.liquibase.org/xml/ns/dbchangelog"
            xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
            xsi:schemaLocation="http://www.liquibase.org/xml/ns/dbchangelog
                http://www.liquibase.org/xml/ns/dbchangelog/dbchangelog-latest.xsd">

        <changeSet id="001-create-posts-table" author="blog">
            <createTable tableName="posts">
                <column name="id" type="BIGINT" autoIncrement="true">
                    <constraints primaryKey="true" nullable="false"/>
                </column>
                <column name="title" type="VARCHAR(200)">
                    <constraints nullable="false"/>
                </column>
                <column name="summary" type="VARCHAR(500)"/>
                <column name="content" type="TEXT">
                    <constraints nullable="false"/>
                </column>
                <column name="published_at" type="DATETIME(6)"/>
                <column name="created_at" type="DATETIME(6)">
                    <constraints nullable="false"/>
                </column>
                <column name="updated_at" type="DATETIME(6)">
                    <constraints nullable="false"/>
                </column>
            </createTable>

            <createIndex tableName="posts" indexName="idx_posts_published_at">
                <column name="published_at"/>
            </createIndex>
        </changeSet>

    </databaseChangeLog>

  Notes:
  - DATETIME(6) stores microseconds, matching what Java's LocalDateTime
    holds. Plain DATETIME would silently drop the fractions of a second.
  - The index on published_at backs the home page query, which filters and
    sorts on that column.
  - Never edit a changeset after it has run anywhere. Liquibase stores a
    checksum of each one and refuses to start if it changes. Fix mistakes
    with a new changeset instead.

3.5 The Post entity

  Create blog/src/main/java/com/blog/post/Post.java:

    package com.blog.post;

    import jakarta.persistence.Column;
    import jakarta.persistence.Entity;
    import jakarta.persistence.GeneratedValue;
    import jakarta.persistence.GenerationType;
    import jakarta.persistence.Id;
    import jakarta.persistence.Table;
    import org.hibernate.annotations.CreationTimestamp;
    import org.hibernate.annotations.UpdateTimestamp;

    import java.time.LocalDateTime;

    @Entity
    @Table(name = "posts")
    public class Post {

        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        private Long id;

        @Column(nullable = false, length = 200)
        private String title;

        @Column(length = 500)
        private String summary;

        @Column(nullable = false, columnDefinition = "TEXT")
        private String content;

        private LocalDateTime publishedAt;

        @CreationTimestamp
        @Column(nullable = false, updatable = false)
        private LocalDateTime createdAt;

        @UpdateTimestamp
        @Column(nullable = false)
        private LocalDateTime updatedAt;

        protected Post() {
        }

        public Post(String title, String summary, String content) {
            this.title = title;
            this.summary = summary;
            this.content = content;
        }

        public void publish(LocalDateTime publishedAt) {
            this.publishedAt = publishedAt;
        }

        public boolean isPublished() {
            return publishedAt != null;
        }

        public Long getId() {
            return id;
        }

        public String getTitle() {
            return title;
        }

        public String getSummary() {
            return summary;
        }

        public String getContent() {
            return content;
        }

        public LocalDateTime getPublishedAt() {
            return publishedAt;
        }

        public LocalDateTime getCreatedAt() {
            return createdAt;
        }

        public LocalDateTime getUpdatedAt() {
            return updatedAt;
        }
    }

  Notes:
  - GenerationType.IDENTITY matches MySQL's AUTO_INCREMENT column.
  - columnDefinition = "TEXT" tells Hibernate's schema validation to
    expect a TEXT column rather than VARCHAR(255).
  - publishedAt needs no @Column: Spring Boot's naming strategy maps
    publishedAt to published_at automatically.
  - @CreationTimestamp and @UpdateTimestamp make Hibernate fill in the
    timestamps, so no code has to remember to set them.
  - JPA needs the no-argument constructor. It is protected so application
    code uses the real constructor instead.
  - There are no setters. State changes go through methods that say what
    they mean, such as publish(...). Step 005 adds an update method.


3.6 Repository, summary record, and service

  Create blog/src/main/java/com/blog/post/PostRepository.java:

    package com.blog.post;

    import org.springframework.data.jpa.repository.JpaRepository;

    import java.util.List;

    interface PostRepository extends JpaRepository<Post, Long> {

        List<Post> findByPublishedAtIsNotNullOrderByPublishedAtDesc();
    }

  Spring Data turns the method name into SQL: WHERE published_at IS NOT
  NULL ORDER BY published_at DESC. Step 003 replaces the List with a page
  of results.

  Create blog/src/main/java/com/blog/post/PostSummary.java:

    package com.blog.post;

    import java.time.LocalDateTime;

    public record PostSummary(Long id, String title, String summary, LocalDateTime publishedAt) {

        static PostSummary from(Post post) {
            return new PostSummary(post.getId(), post.getTitle(), post.getSummary(), post.getPublishedAt());
        }
    }

  Create blog/src/main/java/com/blog/post/PostService.java:

    package com.blog.post;

    import org.springframework.stereotype.Service;
    import org.springframework.transaction.annotation.Transactional;

    import java.util.List;

    @Service
    @Transactional(readOnly = true)
    public class PostService {

        private final PostRepository postRepository;

        PostService(PostRepository postRepository) {
            this.postRepository = postRepository;
        }

        public List<PostSummary> findPublished() {
            return postRepository.findByPublishedAtIsNotNullOrderByPublishedAtDesc()
                    .stream()
                    .map(PostSummary::from)
                    .toList();
        }
    }

  @Transactional(readOnly = true) on the class makes every method read-only
  by default. Hibernate then skips checking loaded entities for changes,
  and the MySQL driver can tell the server it is a read. Methods that write
  (step 005) will override it with a plain @Transactional.


3.7 Controller

  Replace blog/src/main/java/com/blog/web/HomeController.java:

    package com.blog.web;

    import com.blog.post.PostService;
    import org.springframework.stereotype.Controller;
    import org.springframework.ui.Model;
    import org.springframework.web.bind.annotation.GetMapping;

    @Controller
    class HomeController {

        private final PostService postService;

        HomeController(PostService postService) {
            this.postService = postService;
        }

        @GetMapping("/")
        String home(Model model) {
            model.addAttribute("posts", postService.findPublished());
            return "home";
        }

        @GetMapping("/about")
        String about() {
            return "about";
        }
    }

  Constructor injection with a final field. With a single constructor,
  Spring needs no @Autowired.

  Notes:
  - th:text always HTML-escapes its value, so a title containing <script>
    is shown as text, not run. Never use th:utext for user content (step
    004 covers rendering Markdown safely).
  - The text inside tags ("Post title", "1 January 2026") is placeholder
    content. You see it when you open the file directly in a browser, and
    Thymeleaf replaces it at runtime.
  - #temporals is built into Thymeleaf 3.1 for java.time values. The
    <time datetime="..."> attribute gives machines the exact timestamp.
  - Post titles are not links yet. Post pages arrive in step 003.

3.12 Repository test

  Create blog/src/test/java/com/blog/post/PostRepositoryTest.java:

    package com.blog.post;

    import com.blog.TestcontainersConfiguration;
    import org.junit.jupiter.api.Test;
    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.boot.data.jpa.test.autoconfigure.DataJpaTest;
    import org.springframework.context.annotation.Import;
    import org.springframework.test.context.ActiveProfiles;

    import java.time.LocalDateTime;
    import java.util.List;

    import static org.assertj.core.api.Assertions.assertThat;

    @DataJpaTest
    @Import(TestcontainersConfiguration.class)
    @ActiveProfiles("test")
    class PostRepositoryTest {

        @Autowired
        private PostRepository postRepository;

        @Test
        void findsOnlyPublishedPostsNewestFirst() {
            Post older = new Post("Older", "summary", "content");
            older.publish(LocalDateTime.of(2026, 1, 1, 10, 0));
            Post newer = new Post("Newer", "summary", "content");
            newer.publish(LocalDateTime.of(2026, 2, 1, 10, 0));
            Post draft = new Post("Draft", "summary", "content");
            postRepository.saveAll(List.of(older, newer, draft));

            assertThat(postRepository.findByPublishedAtIsNotNullOrderByPublishedAtDesc())
                    .extracting(Post::getTitle)
                    .containsExactly("Newer", "Older");
        }

        @Test
        void setsTimestampsOnSave() {
            Post saved = postRepository.saveAndFlush(new Post("Title", null, "content"));

            assertThat(saved.getCreatedAt()).isNotNull();
            assertThat(saved.getUpdatedAt()).isNotNull();
        }
    }

  Notes:
  - The test sits in the com.blog.post package, so it can use the
    package-private repository.
  - @DataJpaTest wraps each test in a transaction that is rolled back
    afterwards, so tests do not see each other's data.
  - By default @DataJpaTest would swap the datasource for an in-memory
    database. Because TestcontainersConfiguration provides a
    @ServiceConnection, Spring Boot keeps the MySQL container instead.
  - In Spring Boot 4, @DataJpaTest is in
    org.springframework.boot.data.jpa.test.autoconfigure.


3.13 Controller test

  Replace blog/src/test/java/com/blog/web/HomeControllerTest.java:

    package com.blog.web;

    import com.blog.post.PostService;
    import com.blog.post.PostSummary;
    import org.junit.jupiter.api.Test;
    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest;
    import org.springframework.test.context.bean.override.mockito.MockitoBean;
    import org.springframework.test.web.servlet.MockMvc;

    import java.time.LocalDateTime;
    import java.util.List;

    import static org.hamcrest.Matchers.containsString;
    import static org.mockito.BDDMockito.given;
    import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
    import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
    import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;
    import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.view;

    @WebMvcTest(HomeController.class)
    class HomeControllerTest {

        @Autowired
        private MockMvc mockMvc;

        @MockitoBean
        private PostService postService;

        @Test
        void homePageListsPublishedPosts() throws Exception {
            given(postService.findPublished()).willReturn(List.of(
                    new PostSummary(1L, "First post", "A short summary", LocalDateTime.of(2026, 9, 1, 9, 0))));

            mockMvc.perform(get("/").header("Accept-Language", "de-DE"))
                    .andExpect(status().isOk())
                    .andExpect(view().name("home"))
                    .andExpect(content().string(containsString("First post")))
                    .andExpect(content().string(containsString("A short summary")))
                    .andExpect(content().string(containsString("1 September 2026")));
        }

        @Test
        void homePageShowsEmptyState() throws Exception {
            given(postService.findPublished()).willReturn(List.of());

            mockMvc.perform(get("/"))
                    .andExpect(status().isOk())
                    .andExpect(content().string(containsString("No posts have been published yet.")));
        }

        @Test
        void aboutPageRenders() throws Exception {
            mockMvc.perform(get("/about"))
                    .andExpect(status().isOk())
                    .andExpect(view().name("about"));
        }
    }

  Notes:
  - @MockitoBean (from Spring Framework) replaces the old @MockBean, which
    was removed in Spring Boot 4.
  - The German Accept-Language header in the first test checks the fixed

4. VERIFY
---------
  From the blog/ folder, with Docker Desktop running:

  a) Run the tests:

       .\mvnw verify

     Expected: "Tests run: 6, Failures: 0" and "BUILD SUCCESS".

  b) Run the application:

       docker compose up -d mysql
       .\mvnw spring-boot:run

     Expected in the log: Liquibase "Run: 2" the first time (the table and
     the sample data). On later starts it shows "Run: 0, Previously run: 2".

     Open http://localhost:8080. You should see three posts, newest first:
       - Testing with real databases     (1 October 2026)
       - Why Liquibase owns the schema   (15 September 2026)
       - Welcome to the blog             (1 September 2026)
     "An unfinished draft" must not appear. The About link in the header
     opens the About page and highlights itself.

  c) Optional: look at the table:

       docker exec -it blog-mysql mysql -ubloguser -pblogpass blogdb -e "SELECT id, title, published_at FROM posts;"

     All four rows are there, including the draft with published_at NULL.

  Troubleshooting
  - "Schema-validation: wrong column type encountered in column [content]":
    the entity and the changeset disagree about the type. Check that the
    content field has columnDefinition = "TEXT".
  - "Validation Failed: 1 changesets check sum": a changeset that already
    ran was edited. In development, reset the database with
    docker compose down -v, then docker compose up -d mysql. In real
    environments, add a new changeset instead.
  - Changes don't show up while the app is running: ./mvnw spring-boot:run
    runs the classes from the last build. DevTools restarts the app only
    when target/classes changes, which happens when your IDE recompiles.
    If you edit in a plain editor, stop the app with Ctrl+C and start it
    again.
