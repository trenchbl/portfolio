STEP 004 - MARKDOWN CONTENT
===========================


1. GOAL
-------
At the end of this step you will have:
- Post content written in Markdown and rendered to HTML on the post page:
  headings, emphasis, lists, quotes, code blocks, tables, strikethrough,
  and automatic links
- Rendering that is safe by design: raw HTML in a post is shown as text,
  and javascript: links are removed
- Styles for rendered Markdown
- A sample post that shows every supported feature
- Unit tests for the renderer, including the security cases


2. CONCEPTS
-----------
Why commonmark-java
  CommonMark is the standard specification of Markdown, and commonmark-java
  is its reference implementation for Java: small, fast, without other
  dependencies, and extended through modules. GitHub-style tables and
  strikethrough are separate extensions, so the project only includes what
  it uses.

Where rendering happens
  The database stores the Markdown source, which step 005's editor needs.
  The service renders it to HTML when a post is read, and puts the result
  in PostDetail.contentHtml. Rendering a post takes well under a
  millisecond, so it is not cached. If that ever changes, the HTML could be
  stored in its own column when a post is saved.

th:utext and why it is safe here
  th:text escapes everything, which is what you want almost everywhere.
  Rendered Markdown is HTML that must reach the browser as HTML, so the
  post page uses th:utext ("unescaped text") for contentHtml, and only
  there. That is only safe because the renderer guarantees two things:
  - escapeHtml(true): any HTML typed into the Markdown, such as <script>
    or <img onerror=...>, comes out as visible text, not as tags.
  - sanitizeUrls(true): links and images may only use safe schemes (http,
    https, mailto, data). A link to javascript:alert(1) gets an empty URL.
  Even if a post is written by an attacker, for example through a stolen
  admin account, it cannot run scripts in visitors' browsers. The renderer
  tests check exactly this.

  Rule of thumb: never pass anything to th:utext that has not been through
  this renderer.

rel="nofollow"
  sanitizeUrls also adds rel="nofollow" to every link, which tells search
  engines not to trust it. That fits comments from strangers. Posts are
  written by the blog's own authors, though, and nofollow would also mark
  links between your own posts as untrusted. An attribute provider removes
  it from links. The URL sanitizing stays in place.

Headings
  The post title is the page's <h1>. Inside posts, start headings at ##
  (h2) so each page has exactly one <h1>, which matters for screen readers
  and search engines.

3.2 The renderer

  Create blog/src/main/java/com/blog/markdown/MarkdownRenderer.java:

    package com.blog.markdown;

    import org.commonmark.Extension;
    import org.commonmark.ext.autolink.AutolinkExtension;
    import org.commonmark.ext.gfm.strikethrough.StrikethroughExtension;
    import org.commonmark.ext.gfm.tables.TablesExtension;
    import org.commonmark.node.Link;
    import org.commonmark.parser.Parser;
    import org.commonmark.renderer.html.HtmlRenderer;
    import org.springframework.stereotype.Component;

    import java.util.List;

    /**
     * Turns Markdown into HTML that is safe to insert into a page unescaped:
     * raw HTML in the input is escaped, and links or images with unsafe
     * schemes such as {@code javascript:} lose their URL.
     */
    @Component
    public class MarkdownRenderer {

        private static final List<Extension> EXTENSIONS = List.of(
                TablesExtension.create(),
                StrikethroughExtension.create(),
                AutolinkExtension.create());

        private final Parser parser = Parser.builder()
                .extensions(EXTENSIONS)
                .build();

        private final HtmlRenderer renderer = HtmlRenderer.builder()
                .extensions(EXTENSIONS)
                .escapeHtml(true)
                .sanitizeUrls(true)
                // sanitizeUrls also marks every link rel="nofollow", which suits untrusted
                // content such as comments, but posts are written by the blog's own authors
                .attributeProviderFactory(context -> (node, tagName, attributes) -> {
                    if (node instanceof Link) {
                        attributes.remove("rel");
                    }
                })
                .build();

        public String toHtml(String markdown) {
            return renderer.render(parser.parse(markdown));
        }
    }

  Notes:
  - It lives in its own package (com.blog.markdown) because it knows
    nothing about posts. Step 005's preview, or comments later, can reuse
    it.
  - Parser and HtmlRenderer are thread-safe once built, so one instance of
    each serves all requests. As a Spring @Component, there is only one
    MarkdownRenderer in the application.
  - The extensions must be registered on both the parser (to recognise
    the syntax) and the renderer (to output the HTML).

3.7 Renderer tests

  Create blog/src/test/java/com/blog/markdown/MarkdownRendererTest.java:

    package com.blog.markdown;

    import org.junit.jupiter.api.Test;

    import static org.assertj.core.api.Assertions.assertThat;

    class MarkdownRendererTest {

        private final MarkdownRenderer renderer = new MarkdownRenderer();

        @Test
        void rendersParagraphsAndEmphasis() {
            assertThat(renderer.toHtml("First **bold** paragraph.\n\nSecond *one*."))
                    .isEqualTo("<p>First <strong>bold</strong> paragraph.</p>\n<p>Second <em>one</em>.</p>\n");
        }

        @Test
        void rendersHeadingsListsAndCode() {
            String html = renderer.toHtml("""
                    ## Heading

                    - one
                    - two

                    ```java
                    var x = 1;
                    ```
                    """);

            assertThat(html)
                    .contains("<h2>Heading</h2>")
                    .contains("<ul>\n<li>one</li>\n<li>two</li>\n</ul>")
                    .contains("<pre><code class=\"language-java\">var x = 1;\n</code></pre>");
        }

        @Test
        void rendersGithubFlavouredExtensions() {
            String html = renderer.toHtml("""
                    | A | B |
                    |---|---|
                    | 1 | 2 |

                    ~~gone~~ and https://example.com
                    """);

            assertThat(html)
                    .contains("<table>")
                    .contains("<td>1</td>")
                    .contains("<del>gone</del>")
                    .contains("<a href=\"https://example.com\">https://example.com</a>");
        }

        @Test
        void escapesRawHtml() {
            String html = renderer.toHtml("Hello <script>alert('x')</script> and <b onclick=\"x()\">bold</b>");

            assertThat(html)
                    .doesNotContain("<script>")
                    .doesNotContain("<b ")
                    .contains("&lt;script&gt;");
        }

        @Test
        void escapesRawHtmlBlocks() {
            String html = renderer.toHtml("<div>\n<img src=x onerror=alert(1)>\n</div>");

            assertThat(html)
                    .doesNotContain("<div>")
                    .doesNotContain("<img")
                    .contains("&lt;img");
        }

        @Test
        void removesJavascriptLinks() {
            String html = renderer.toHtml("[click me](javascript:alert(1)) and ![image](javascript:alert(2))");

            assertThat(html).doesNotContainIgnoringCase("javascript:");
        }

        @Test
        void keepsSafeLinks() {
            assertThat(renderer.toHtml("[Spring](https://spring.io) and [mail](mailto:me@example.com)"))
                    .contains("<a href=\"https://spring.io\">Spring</a>")
                    .contains("<a href=\"mailto:me@example.com\">mail</a>");
        }
    }

  This is a plain JUnit test with no Spring context, because the renderer
  has no dependencies. All seven tests run in well under a second.

  The Markdown in the text blocks (""") is indented in the Java source.
  Java removes the common indentation, so the renderer sees lines starting
  at column 0.

  escapesRawHtml and escapesRawHtmlBlocks cover the two ways HTML can
  appear in Markdown: inline inside a paragraph, and as a block on its own
  lines. removesJavascriptLinks covers both links and images.
  keepsSafeLinks also checks that no rel="nofollow" is added.

        @Test

                    .andExpect(status().isOk())

  Troubleshooting
  - The whole sample post shows as one grey code block: the CDATA lines are
    indented. Markdown treats four leading spaces as code. Since 005 has
    already run, fix it with a new changeset (an <update> of that row) or,
    in development, see step 003 for the checksum options.
  - Tables or ~~strikethrough~~ show as plain text: the extension is missing
    from the parser or the renderer. It must be registered on both.
