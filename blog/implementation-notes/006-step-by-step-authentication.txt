STEP 006 - AUTHENTICATION WITH SPRING SECURITY
==============================================


1. GOAL
-------
At the end of this step you will have:
- /admin/** only reachable by a logged-in admin; visitors are sent to a
  login page
- A login page at /login with your own layout, and "Log out" in the header
- User accounts in the database, with passwords stored as bcrypt hashes
- The first admin account created on startup from configuration, so no
  password ever ends up in a changeset or in Git
- CSRF protection on every form
- "Admin" and "Log out" in the header only for admins
- A friendly 403 page


2. CONCEPTS
-----------
The filter chain
  Spring Security is a chain of servlet filters that runs before any
  controller. Adding the starter alone locks down every URL and generates a
  default login page with a random password. A SecurityFilterChain bean
  replaces those defaults with your own rules:
  - /admin/** needs the ADMIN role
  - everything else is public
  Rules are checked top to bottom, and the first match wins, so put
  specific paths first and anyRequest() last.

Authentication vs. authorization
  Authentication asks "who are you?": the login form checks the username
  and password. Authorization asks "what may you do?": hasRole("ADMIN")
  on /admin/**. A visitor who is not logged in is redirected to /login. A
  logged-in user without the role gets 403 Forbidden.

Roles and authorities
  hasRole("ADMIN") checks for the authority "ROLE_ADMIN". The builder
  User.withUsername(...).roles("ADMIN") adds the "ROLE_" prefix for you.
  The database stores only "ADMIN".

UserDetailsService
  The login form gives Spring Security a username and password. It asks
  your UserDetailsService to load the user by name, then compares the
  password with the stored hash itself. You never compare passwords in
  your own code. An unknown user and a wrong password give the same
  "incorrect" message, so the login page does not reveal which usernames
  exist.

Password hashing
  Passwords are never stored. A hash is: bcrypt is deliberately slow and
  adds a random salt, so two users with the same password get different
  hashes, and a stolen table is expensive to crack.
  PasswordEncoderFactories.createDelegatingPasswordEncoder() stores the
  algorithm in front of the hash ("{bcrypt}$2a$10$..."). If you move to a
  stronger algorithm later, old hashes keep working, because each hash
  says how it was made.

The first admin
  Somebody has to exist before anyone can log in. Putting a user in a
  changeset would put a password hash in Git, and it would be the same on
  every installation. Instead, an ApplicationRunner checks at startup: if
  the users table is empty and blog.admin.username and blog.admin.password
  are set, it creates the admin with a hashed password. Once a user exists,
  the settings are ignored, so you can remove the password afterwards.
  On your machine the settings live in application-local.properties, which
  Git ignores. On a server (step 009) they come from the
  BLOG_ADMIN_USERNAME and BLOG_ADMIN_PASSWORD environment variables. Spring
  Boot maps those names to blog.admin.username and blog.admin.password
  automatically.

CSRF (cross-site request forgery)
  While you are logged in, your browser sends the session cookie with
  every request to the blog, including requests that another website
  triggers. Without protection, a malicious page could contain a hidden
  form that posts to /admin/posts/1/delete, and the browser would send it
  with your cookie.
  Spring Security therefore requires a secret token on every POST, PUT,
  PATCH, and DELETE. The token is stored in your session and is unknown to
  other sites. Thymeleaf adds it to every form that uses th:action, as a
  hidden _csrf field. That is the reason all forms in this project use
  th:action instead of a plain action attribute. GET requests are not
  checked, which is one more reason never to change data with GET (step
  005).

Logout is a POST
  With CSRF enabled, logout only works as POST /logout with the token. A
  plain <a href="/logout"> link would let any website log you out. So
  "Log out" in the header is a small form with a button styled as a link.

Saved requests
  When a visitor opens /admin/posts/3/edit and is sent to the login page,
  Spring Security remembers that URL. After login, it sends them back to
  it, with "?continue" added, instead of the default /admin/posts.

sec:authorize in templates
  The thymeleaf-extras-springsecurity6 module adds the sec: attributes.
  sec:authorize="hasRole('ADMIN')" renders an element only for admins.
  This only hides links. The filter chain is what actually protects the
  pages.

    import jakarta.persistence.Column;
    import jakarta.persistence.Entity;
    import jakarta.persistence.EnumType;
    import jakarta.persistence.Enumerated;
    import jakarta.persistence.GeneratedValue;
    import jakarta.persistence.GenerationType;
    import jakarta.persistence.Id;
    import jakarta.persistence.Table;
    import org.hibernate.annotations.CreationTimestamp;

    import java.time.LocalDateTime;

    /**
     * Named UserAccount rather than User to avoid confusion with Spring
     * Security's {@code User} class.
     */
    @Entity
    @Table(name = "users")
    public class UserAccount {

        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        private Long id;

        @Column(nullable = false, length = 50)
        private String username;

        @Column(nullable = false)
        private String passwordHash;

        @Enumerated(EnumType.STRING)
        @Column(nullable = false, length = 20)
        private Role role;

        @Column(nullable = false)
        private boolean enabled = true;

        @CreationTimestamp
        @Column(nullable = false, updatable = false)
        private LocalDateTime createdAt;

        protected UserAccount() {
        }

        public UserAccount(String username, String passwordHash, Role role) {
            this.username = username;
            this.passwordHash = passwordHash;
            this.role = role;
        }

        public Long getId() {
            return id;
        }

        public String getUsername() {
            return username;
        }

        public String getPasswordHash() {
            return passwordHash;
        }

        public Role getRole() {
            return role;
        }

        public boolean isEnabled() {
            return enabled;
        }

        public LocalDateTime getCreatedAt() {
            return createdAt;
        }
    }

  blog/src/main/java/com/blog/user/DatabaseUserDetailsService.java:

    package com.blog.user;

    import org.springframework.security.core.userdetails.User;
    import org.springframework.security.core.userdetails.UserDetails;
    import org.springframework.security.core.userdetails.UserDetailsService;
    import org.springframework.security.core.userdetails.UsernameNotFoundException;
    import org.springframework.stereotype.Service;
    import org.springframework.transaction.annotation.Transactional;

    @Service
    @Transactional(readOnly = true)
    class DatabaseUserDetailsService implements UserDetailsService {

        private final UserAccountRepository userAccountRepository;

        DatabaseUserDetailsService(UserAccountRepository userAccountRepository) {
            this.userAccountRepository = userAccountRepository;
        }

        @Override
        public UserDetails loadUserByUsername(String username) {
            UserAccount account = userAccountRepository.findByUsername(username)
                    .orElseThrow(() -> new UsernameNotFoundException("No user named '" + username + "'"));
            return User.withUsername(account.getUsername())
                    .password(account.getPasswordHash())
                    .roles(account.getRole().name())
                    .disabled(!account.isEnabled())
                    .build();
        }
    }

  When there is exactly one UserDetailsService bean and one
  PasswordEncoder bean, Spring Security wires them into the login form by
  itself. The class can stay package-private.

  blog/src/main/java/com/blog/user/InitialAdminProperties.java:

    package com.blog.user;

    import org.springframework.boot.context.properties.ConfigurationProperties;

    /**
     * Credentials for the first admin account, read from blog.admin.username and
     * blog.admin.password (or the BLOG_ADMIN_USERNAME and BLOG_ADMIN_PASSWORD
     * environment variables). Only used while the users table is empty.
     */
    @ConfigurationProperties("blog.admin")
    record InitialAdminProperties(String username, String password) {

        boolean isConfigured() {
            return username != null && !username.isBlank() && password != null && !password.isBlank();
        }
    }

  blog/src/main/java/com/blog/user/InitialAdminCreator.java:

    package com.blog.user;

    import org.slf4j.Logger;
    import org.slf4j.LoggerFactory;
    import org.springframework.boot.ApplicationArguments;
    import org.springframework.boot.ApplicationRunner;
    import org.springframework.boot.context.properties.EnableConfigurationProperties;
    import org.springframework.security.crypto.password.PasswordEncoder;
    import org.springframework.stereotype.Component;
    import org.springframework.transaction.annotation.Transactional;

    /**
     * Creates the first admin account on startup when there are no users yet.
     * After that, the configured credentials are ignored.
     */
    @Component
    @EnableConfigurationProperties(InitialAdminProperties.class)
    class InitialAdminCreator implements ApplicationRunner {

        static final int MIN_PASSWORD_LENGTH = 12;

        private static final Logger log = LoggerFactory.getLogger(InitialAdminCreator.class);

        private final UserAccountRepository userAccountRepository;
        private final PasswordEncoder passwordEncoder;
        private final InitialAdminProperties properties;

        InitialAdminCreator(UserAccountRepository userAccountRepository, PasswordEncoder passwordEncoder,
                            InitialAdminProperties properties) {
            this.userAccountRepository = userAccountRepository;
            this.passwordEncoder = passwordEncoder;
            this.properties = properties;
        }

        @Override
        @Transactional
        public void run(ApplicationArguments args) {
            if (userAccountRepository.count() > 0) {
                return;
            }
            if (!properties.isConfigured()) {
                log.warn("There are no user accounts, so nobody can log in. Set blog.admin.username and "
                        + "blog.admin.password (or BLOG_ADMIN_USERNAME and BLOG_ADMIN_PASSWORD) and restart.");
                return;
            }
            if (properties.password().length() < MIN_PASSWORD_LENGTH) {
                throw new IllegalStateException(
                        "blog.admin.password must be at least " + MIN_PASSWORD_LENGTH + " characters long");
            }
            String username = properties.username().strip();
            userAccountRepository.save(new UserAccount(username, passwordEncoder.encode(properties.password()), Role.ADMIN));
            log.info("Created the first admin account '{}'. You can remove blog.admin.password from the configuration now.",
                    username);
        }
    }

  Notes:
  - ApplicationRunner runs after the context has started, so Liquibase has
    already created the users table.
  - Without settings, the app still starts and logs a warning, so the
    public blog keeps working. A password that is too short stops the app
    instead: a weak admin password should never go unnoticed.
  - The log message names the user but never the password.

3.4 The security configuration

  blog/src/main/java/com/blog/security/SecurityConfig.java:

    package com.blog.security;

    import org.springframework.context.annotation.Bean;
    import org.springframework.context.annotation.Configuration;
    import org.springframework.security.config.annotation.web.builders.HttpSecurity;
    import org.springframework.security.crypto.factory.PasswordEncoderFactories;
    import org.springframework.security.crypto.password.PasswordEncoder;
    import org.springframework.security.web.SecurityFilterChain;

    @Configuration
    public class SecurityConfig {

        @Bean
        SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
            http
                    .authorizeHttpRequests(requests -> requests
                            .requestMatchers("/admin/**").hasRole("ADMIN")
                            .anyRequest().permitAll())
                    .formLogin(form -> form
                            .loginPage("/login")
                            .defaultSuccessUrl("/admin/posts"))
                    .logout(logout -> logout
                            .logoutSuccessUrl("/login?logout"));
            return http.build();
        }

        @Bean
        PasswordEncoder passwordEncoder() {
            return PasswordEncoderFactories.createDelegatingPasswordEncoder();
        }
    }

  Notes:
  - The class is public because the @WebMvcTest tests import it (3.9).
  - CSRF protection is on by default, so it does not appear here.
  - loginPage("/login") replaces the generated login page. Spring Security
    still handles POST /login itself: it reads the "username" and
    "password" fields, checks them, and redirects to /login?error when
    they are wrong.
  - Static files (/css/**) and the error pages fall under permitAll().

  Use a real password, for example one generated by your password manager.
  Check that Git ignores the file:

    git check-ignore -v application-local.properties

    package com.blog.user;

    import org.junit.jupiter.api.Test;
    import org.springframework.security.crypto.factory.PasswordEncoderFactories;
    import org.springframework.security.crypto.password.PasswordEncoder;

    import static org.assertj.core.api.Assertions.assertThat;
    import static org.assertj.core.api.Assertions.assertThatThrownBy;
    import static org.mockito.ArgumentMatchers.any;
    import static org.mockito.ArgumentMatchers.argThat;
    import static org.mockito.BDDMockito.given;
    import static org.mockito.Mockito.mock;
    import static org.mockito.Mockito.never;
    import static org.mockito.Mockito.verify;

    class InitialAdminCreatorTest {

        private static final String PASSWORD = "a-long-enough-password";

        private final UserAccountRepository repository = mock(UserAccountRepository.class);
        private final PasswordEncoder passwordEncoder = PasswordEncoderFactories.createDelegatingPasswordEncoder();

        @Test
        void createsTheAdminWithAHashedPasswordWhenThereAreNoUsers() {
            given(repository.count()).willReturn(0L);

            creator(" admin ", PASSWORD).run(null);

            verify(repository).save(argThat(account ->
                    account.getUsername().equals("admin")
                            && account.getRole() == Role.ADMIN
                            && account.getPasswordHash().startsWith("{bcrypt}")
                            && passwordEncoder.matches(PASSWORD, account.getPasswordHash())));
        }

        @Test
        void doesNothingWhenUsersExist() {
            given(repository.count()).willReturn(1L);

            creator("admin", PASSWORD).run(null);

            verify(repository, never()).save(any());
        }

        @Test
        void doesNothingWhenNotConfigured() {
            given(repository.count()).willReturn(0L);

            creator(null, null).run(null);
            creator("admin", "  ").run(null);

            verify(repository, never()).save(any());
        }

        @Test
        void refusesShortPasswords() {
            given(repository.count()).willReturn(0L);

            assertThatThrownBy(() -> creator("admin", "short").run(null))
                    .isInstanceOf(IllegalStateException.class)
                    .hasMessageContaining("at least " + InitialAdminCreator.MIN_PASSWORD_LENGTH);
            verify(repository, never()).save(any());
        }

        @Test
        void passwordHashesAreSalted() {
            assertThat(passwordEncoder.encode(PASSWORD)).isNotEqualTo(passwordEncoder.encode(PASSWORD));
        }

        private InitialAdminCreator creator(String username, String password) {
            return new InitialAdminCreator(repository, passwordEncoder, new InitialAdminProperties(username, password));
        }
    }

    import org.springframework.test.web.servlet.MvcResult;

    import static org.assertj.core.api.Assertions.assertThat;
    import static org.hamcrest.Matchers.containsString;
    import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestBuilders.formLogin;
    import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.csrf;
    import static org.springframework.security.test.web.servlet.response.SecurityMockMvcResultMatchers.authenticated;
    import static org.springframework.security.test.web.servlet.response.SecurityMockMvcResultMatchers.unauthenticated;
    import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
    import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
    import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
    import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.redirectedUrl;
    import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

    /**
     * The whole chain on a real database: the first admin is created from
     * configuration, and logging in checks the password against its hash.
     */
    @SpringBootTest(properties = {
            "blog.admin.username=" + LoginFlowTest.USERNAME,
            "blog.admin.password=" + LoginFlowTest.PASSWORD
    })
    @AutoConfigureMockMvc
    @Import(TestcontainersConfiguration.class)
    @ActiveProfiles("test")
    class LoginFlowTest {

        static final String USERNAME = "editor";
        static final String PASSWORD = "correct-horse-battery-staple";

        @Autowired
        private MockMvc mockMvc;

        @Autowired
        private UserAccountRepository userAccountRepository;

        @Test
        void createsTheConfiguredAdminWithAHashedPassword() {
            UserAccount account = userAccountRepository.findByUsername(USERNAME).orElseThrow();

            assertThat(account.getRole()).isEqualTo(Role.ADMIN);
            assertThat(account.getPasswordHash()).startsWith("{bcrypt}").doesNotContain(PASSWORD);
        }

        @Test
        void loginPageIsPublic() throws Exception {
            mockMvc.perform(get("/login"))
                    .andExpect(status().isOk())
                    .andExpect(content().string(containsString("name=\"_csrf\"")));
        }

        @Test
        void adminPagesRequireLogin() throws Exception {
            mockMvc.perform(get("/admin/posts"))
                    .andExpect(status().is3xxRedirection())
                    .andExpect(redirectedUrl("/login"));
        }

        @Test
        void wrongPasswordIsRejected() throws Exception {
            mockMvc.perform(formLogin().user(USERNAME).password("wrong-password"))
                    .andExpect(redirectedUrl("/login?error"))
                    .andExpect(unauthenticated());
        }

        @Test
        void unknownUserIsRejected() throws Exception {
            mockMvc.perform(formLogin().user("nobody").password(PASSWORD))
                    .andExpect(redirectedUrl("/login?error"))
                    .andExpect(unauthenticated());
        }

        @Test
        void loginGivesAccessToTheAdminPagesUntilLogout() throws Exception {
            MvcResult login = mockMvc.perform(formLogin().user(USERNAME).password(PASSWORD))
                    .andExpect(redirectedUrl("/admin/posts"))
                    .andExpect(authenticated().withUsername(USERNAME).withRoles("ADMIN"))
                    .andReturn();
            MockHttpSession session = (MockHttpSession) login.getRequest().getSession(false);

            mockMvc.perform(get("/admin/posts").session(session))
                    .andExpect(status().isOk())
                    .andExpect(content().string(containsString("Log out")));

            mockMvc.perform(post("/logout").with(csrf()).session(session))
                    .andExpect(redirectedUrl("/login?logout"))
                    .andExpect(unauthenticated());

            mockMvc.perform(get("/admin/posts").session(session))
                    .andExpect(redirectedUrl("/login"));
        }
    }

  Notes:
  - formLogin() posts to /login with the username, password, and a valid
    CSRF token, like the real form.
  - The properties in @SpringBootTest take priority over
    application-local.properties, so the test does not depend on your
    local password.
  - The last test reuses the session from the login, the way a browser
    reuses its cookie.

  b) Run the application:

     Then:
     1. Open http://localhost:8080. The header shows Home and About, but
        no Admin.
     2. Open http://localhost:8080/admin/posts. You land on the login page.
     3. Log in with a wrong password: "The username or password is
        incorrect."
     4. Log in with the password from application-local.properties. You

     5. In the browser's developer tools, look at the "New post" form. It
        contains <input type="hidden" name="_csrf" ...>.
     6. Click "Log out": "You have been logged out." /admin/posts sends you

     7. Restart the app. The admin message does not appear again, because
        the user already exists.

       docker exec -it blog-mysql mysql -ubloguser -pblogpass blogdb -e "SELECT username, role, LEFT(password_hash, 12) FROM users;"

     Expected: admin, ADMIN, {bcrypt}$2a$1 (never the password itself).

  d) Optional: prove CSRF protection works. In the developer tools, delete
     the hidden _csrf field from a delete form, then click Delete. You get
     the "Access denied" page, and the post is still there.

  Troubleshooting
  - "Schema validation: wrong column type encountered in column [enabled]
    ... found [tinyint], but expecting [bit]": the changeset uses type
    BOOLEAN. Use BIT(1). If 007 already ran with the wrong type, drop the
    users table and delete the 007 row from DATABASECHANGELOG, then
    restart (only on your own dev database).
  - The browser shows Spring's plain login page, and the log prints "Using
    generated security password": SecurityConfig is not being picked up.
    It must be in a package under com.blog, and annotated with
    @Configuration.
  - The log says "There are no user accounts, so nobody can log in":
    application-local.properties was not found. It must be next to
    pom.xml, and you must start the app from the blog folder.
  - The app stops with "blog.admin.password must be at least 12
    characters long": choose a longer password.
  - You changed the password in application-local.properties, but the old
    one still works: that is expected. The settings only create the first
    admin. On your dev database, you can delete the row (DELETE FROM
    users;) and restart to create it again.
  - Every form submit gives "Access denied": the form uses action="..."
    instead of th:action="@{...}", so it has no CSRF token.
  - @WebMvcTest tests suddenly get 401 or 403 everywhere: the test class
    lacks @Import(SecurityConfig.class), so Spring Boot's default rules
    apply.
  - Admin and Log out are not shown after login: the xmlns:sec namespace is
    missing, or thymeleaf-extras-springsecurity6 is not in the pom.
